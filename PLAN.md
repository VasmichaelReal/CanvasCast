# CanvasCast — Архітектура, стек та план імплементації MVP

> Інклюзивний AI-гід для мистецьких просторів. Перетворює візуальне мистецтво на
> художню аудіодескрипцію для людей із порушеннями зору. Без реєстрації, без
> встановлення застосунку — доступ через QR-код / посилання, з офлайн-режимом.

**Статус документа:** план для хакатону з перспективою масштабування.
**Дата:** 2026-11-16.

---

## 1. Контекст і цілі

### Проблема
Візуальне мистецтво майже недоступне для людей із порушеннями зору. Малі галереї
не мають бюджету на професійну тифлокоментування, а готових якісних описів не існує.

### Рішення
Веб-застосунок на базі закритої бази знань конкретної галереї, який автоматично
генерує **художню** аудіодескрипцію (композиція, плани, пози/погляди/жести,
колір через відчуття тепла-прохолоди-м'якості-різкості, атмосфера епохи) і озвучує її.

### Головні обмеження, що формують архітектуру
Ці пункти з бізнес-опису — не «деталі», а те, що безпосередньо диктує рішення:

| Вимога | Архітектурний наслідок |
|---|---|
| Без встановлення, доступ через QR | **PWA**, а не нативний застосунок |
| Без реєстрації | Доступ через **непередбачувані токени** (view + edit), не акаунти |
| Офлайн-режим (тексти + аудіо + зображення) | **Service Worker + Cache API**, кешування медіа одним натисканням |
| Генерація дорога і може падати | **Черга задач** з ретраями, лімітами й ідемпотентністю |
| AI/TTS можуть помилятися / змінювати ціну | **Адаптери провайдерів** + ручне редагування опису |
| Цільова аудиторія — незрячі | **WCAG 2.2 AA** як first-class вимога, не «потім» |
| Ринок ЄС, персональні дані | **GDPR-дружній** хостинг і мінімізація даних |

## 2. Технологічний стек

Єдина мова (**TypeScript**) на всьому стеку — швидкість для хакатону + спільні типи
між фронтом, API та воркером.

| Шар | Технологія | Обґрунтування |
|---|---|---|
| Фронтенд / PWA | **Next.js (App Router) + React + TypeScript** | SSR/SSG для швидкого first paint, вбудований API-шар, зріла a11y-екосистема |
| UI / стилі | **Tailwind CSS + Radix UI / React Aria** | Radix/React Aria дають доступні за замовчуванням компоненти (фокус, ARIA, клавіатура) |
| Стейт/дані | **TanStack Query** | Кешування, офлайн-ретраї, синхронізація |
| PWA / офлайн | **Service Worker (Workbox) + Cache API + IndexedDB** | Кеш текстів/аудіо/зображень, статус готовності, оновлення копії |
| API | **Next.js Route Handlers** (REST) | Один деплой для MVP; за потреби легко винести в окремий сервіс |
| Валідація | **Zod** | Спільні схеми запит/відповідь, рантайм-валідація завантажень |
| ORM / БД | **Prisma + PostgreSQL** | Типобезпека, міграції; Postgres надійний для реляційних сутностей |
| Кеш / черга | **Redis + BullMQ** | Асинхронна генерація, ретраї, rate-limit, пріоритети |
| Воркер | **Node.js (окремий процес) на BullMQ** | Довготривалі задачі генерації поза запит-відповідь циклом |
| Сховище файлів | **S3-сумісне (Cloudflare R2 / AWS S3 / MinIO)** | Зображення + аудіо; CDN-роздача; R2 без egress-плати |
| Опис (LLM) | **Адаптер `LLMProvider`** — дефолт **Gemini Flash (free tier)**; апгрейд → Claude vision | Безкоштовний старт з vision + укр. мовою; перехід на якісніший Claude без зміни коду |
| Озвучення (TTS) | **Адаптер провайдерів** (див. §6) | Дефолт — безкоштовний/дешевий; апгрейд без зміни коду |
| QR | бібліотека генерації QR (`qrcode`) | Генерація PNG/SVG на боці сервера |
| Тести | **Vitest + Playwright + axe-core** | Юніт, E2E, автоматична a11y-перевірка |
| Спостережуваність | **Sentry + структуровані логи** | Помилки генерації, падіння воркера |

### Чому не нативний застосунок і не окремий Python-бекенд
- **Натив** суперечить вимозі «відсканував QR — користуєшся», тому PWA.
- **Окремий Python** додав би другу мову й окремий деплой; вигода (ML-екосистема)
  не потрібна, бо генерація — це виклики зовнішніх API, а не власні моделі. Якщо
  в майбутньому з'явиться власна ML-обробка, її легко додати як окремий сервіс за адаптером.

## 3. Архітектура системи (high-level)

Трирівнева схема з винесеною асинхронною генерацією.

```
          ┌───────────────────────────────────────────────┐
          │                Клієнти (браузер)               │
          │                                                │
          │  Власник/Редактор PWA        Відвідувач PWA     │
          │  (editToken)                 (viewToken, офлайн)│
          └───────────────┬───────────────────┬────────────┘
                          │ HTTPS             │ HTTPS
                          ▼                   ▼
          ┌───────────────────────────────────────────────┐
          │           Next.js (App Router)                 │
          │   - SSR сторінки (перегляд/редактор)           │
          │   - REST API (Route Handlers)                  │
          │   - Авторизація за токенами, rate-limit        │
          └───┬───────────────┬───────────────┬────────────┘
              │               │               │
              ▼               ▼               ▼
      ┌────────────┐   ┌────────────┐   ┌──────────────┐
      │ PostgreSQL │   │   Redis    │   │  S3 / R2     │
      │ (Prisma)   │   │  (BullMQ)  │   │ зображення/  │
      │            │   │  черга+    │   │ аудіо (+CDN) │
      │            │   │  кеш+ліміт │   │              │
      └────────────┘   └─────┬──────┘   └──────────────┘
                             │ забирає задачі
                             ▼
          ┌───────────────────────────────────────────────┐
          │              Worker (Node + BullMQ)            │
          │   1) LLM-адаптер → художній опис (uk/en)       │
          │   2) TTS-адаптер → аудіофайл                   │
          │   3) запис у S3 + оновлення статусу в БД       │
          │   ретраї, ліміти вартості, ідемпотентність     │
          └───────────────┬───────────────────────────────┘
                          │ виклики
                          ▼
             ┌─────────────────────────────┐
             │   Зовнішні провайдери        │
             │   Claude (vision) · TTS      │
             └─────────────────────────────┘
```

**Потік генерації:** редактор завантажує фото → API створює `Painting` і кладе
`GenerationJob` у чергу → воркер генерує опис (LLM) → озвучує (TTS) → зберігає
текст+аудіо, виставляє статус `ready` → редактор бачить результат, може
відредагувати й перегенерувати.

## 4. Модель даних

Доступ без акаунтів — через два секретні токени на галерею.

```
Gallery
  id            uuid (pk)
  name          text
  defaultLang   enum(uk, en)
  viewToken     text  (унікальний, у QR/посиланні для перегляду)
  editToken     text  (унікальний, секретний, для редагування)
  createdAt     timestamptz
  updatedAt     timestamptz

Painting
  id            uuid (pk)
  galleryId     uuid (fk → Gallery)
  position      int        (порядок у списку)
  imageKey      text       (ключ у S3: оригінал)
  thumbKey      text       (мінімальне зображення для офлайну)
  title         text?      (необов'язково)
  author        text?      ┐
  year          text?      │ метадані від власника —
  technique     text?      │ ПРІОРИТЕТНЕ джерело фактів для LLM
  context       text?      ┘
  createdAt     timestamptz

Description
  id            uuid (pk)
  paintingId    uuid (fk → Painting)
  lang          enum(uk, en)
  text          text              (згенерований/відредагований)
  textEdited    bool              (чи правив людина)
  audioKey      text?             (ключ аудіо в S3)
  audioDuration int?              (сек, для плеєра/офлайну)
  confidence    enum(high, low)?  (позначка «невпевнені дані»)
  status        enum(pending, generating, ready, failed)
  createdAt     timestamptz
  updatedAt     timestamptz
  UNIQUE(paintingId, lang)

GenerationJob
  id            uuid (pk)
  paintingId    uuid (fk)
  lang          enum(uk, en)
  type          enum(description, tts, full)
  status        enum(queued, running, done, failed)
  attempts      int
  error         text?
  costEstimate  numeric?          (контроль вартості)
  createdAt     timestamptz
```

**Нотатки:**
- `confidence=low` реалізує вимогу «позначати невпевнені дані» (обмеження §5 бізнес-опису).
- `thumbKey` — мінімальне зображення для офлайн-кешу (повні оригінали офлайн не тягнемо).
- Відсутність `editToken` → неможливо відновити доступ (відома межа MVP, див. §12 беклог: e-mail-recovery).

## 5. API (REST, Next.js Route Handlers)

Авторизація: `viewToken` — у шляху/заголовку для публічного; `editToken` — у
заголовку `X-Edit-Token` для мутацій. Усі мутації — rate-limited за IP+token.

### Публічні (перегляд / відвідувач)
```
GET  /api/v/:viewToken/gallery         → метадані галереї + список картин (ready)
GET  /api/v/:viewToken/manifest        → офлайн-маніфест (перелік ресурсів + версії)
GET  /api/media/:key                   → зображення/аудіо (підписаний/кешований URL)
```

### Редактор (власник, editToken)
```
POST   /api/galleries                          → створити галерею (повертає обидва токени + QR)
GET    /api/e/:editToken/gallery               → галерея з усіма статусами
PATCH  /api/e/:editToken/gallery               → назва, мова за замовчуванням
POST   /api/e/:editToken/paintings             → завантажити 1+ зображень (multipart), валідація типу/розміру
PATCH  /api/e/:editToken/paintings/:id         → метадані (автор, рік, техніка, контекст, позиція)
DELETE /api/e/:editToken/paintings/:id         → видалити (API повертає вимогу підтвердження)
POST   /api/e/:editToken/paintings/:id/generate → (пере)генерувати опис+аудіо (ставить job)
PATCH  /api/e/:editToken/descriptions/:id      → ручне редагування тексту
POST   /api/e/:editToken/descriptions/:id/tts  → перегенерувати лише аудіо
GET    /api/e/:editToken/jobs                  → статуси генерації (polling / SSE)
```

**Валідація завантажень:** тип (jpeg/png/webp), розмір (ліміт), кількість; MIME-sniffing,
а не лише розширення.

## 6. AI-пайплайн

### 6.1 Генерація опису (LLM, vision)
- Вхід: **зображення картини + метадані власника** (автор/рік/техніка/контекст).
- Метадані — **пріоритетне джерело фактів** (вимога §3 ФВ); модель не вигадує те,
  що суперечить наданим даним.
- Системний промпт кодує «стиль CanvasCast»: послідовне розкриття простору (передній/
  задній план → пози/погляди/жести → колір через відчуття → атмосфера епохи);
  заборона сухих енциклопедичних штампів, стереотипів, образливих формулювань;
  вихід природною українською/англійською.
- Антигалюцинації: модель відокремлює **спостережуване** від **інтерпретації**;
  непідтверджені факти позначаються → `confidence=low` + видимий маркер у редакторі.
- Модель — за адаптером `LLMProvider` (стратегія «безкоштовно зараз → якісніше потім»):

| Етап | Провайдер | Чому |
|---|---|---|
| MVP / хакатон (дефолт) | **Gemini Flash (free tier)** | Vision + укр. мова безкоштовно, лише API-ключ, без GPU |
| Повний нуль-кост / офлайн-дев | **Ollama + Qwen2-VL (локально)** | Без ключів і мережі; потребує GPU/RAM |
| Апгрейд якості | **Claude (vision), Claude 4.x** | Найкраща «художня» українська; промпт-кешинг системного промпту |

### 6.2 Озвучення (TTS) — провайдер-незалежний адаптер
Інтерфейс:
```ts
interface TtsProvider {
  synthesize(input: {
    text: string; lang: 'uk' | 'en'; voice?: string;
  }): Promise<{ audio: Buffer; mime: string; durationSec: number }>;
}
```

**Стратегія (за вашим рішенням «почати з безкоштовного, потім оптимальніше»):**

| Етап | Провайдер | Чому |
|---|---|---|
| MVP / хакатон (дефолт) | **Piper TTS (self-host, open-source)** або **Google Cloud TTS (free tier)** | Нульова/мінімальна вартість, українські голоси, генерує аудіофайл на сервері (потрібно для офлайн-кешу) |
| Fallback у браузері | **Web Speech API** | Якщо сервер-аудіо недоступне — читання вголос на пристрої (без збереженого файлу) |
| Апгрейд якості | **ElevenLabs / Azure Speech** | Виразніший «художній» голос, SSML для темпу/пауз; вмикається зміною одного адаптера |

Вибір провайдера — через конфіг/feature-flag. Згенероване аудіо зберігається в S3
(вимога «зберігати обидві версії» — текст і аудіо).

### 6.3 Контроль вартості й надійності
- `costEstimate` на задачу; денні/галерейні ліміти → дотримання обмеження «вартість
  генерації < виручки».
- Ретраї з експоненційним backoff у BullMQ; `failed` після N спроб із видимим статусом.
- Ідемпотентність: повторний `generate` для картини не створює дублікатів описів
  (UNIQUE paintingId+lang, оновлення на місці).

## 7. Офлайн-режим та PWA

Критична вимога (ФВ 11). Реалізація:
- **Service Worker (Workbox):** precache оболонки застосунку; runtime-кеш медіа.
- **«Завантажити галерею»** одним натисканням: за `manifest` тягне всі тексти +
  аудіо + мінімальні зображення у Cache API; прогрес і **статус готовності**.
- **IndexedDB:** метадані галереї/картин для роботи списку й плеєра офлайн.
- **Версіонування:** `manifest` містить версії ресурсів → пропозиція «оновити копію»
  за наявності зв'язку.
- **Плеєр:** play/pause, перемотування, зміна швидкості, синхронний показ тексту
  (ФВ 10) — усе працює з кешу.

## 8. Безпека, доступ, приватність

- **HTTPS** скрізь; HSTS.
- **Токени:** довгі (≥128 біт ентропії), непередбачувані, різні для перегляду й
  редагування; `editToken` ніколи не потрапляє у view-відповіді.
- **Rate-limiting** (Redis) на створення галерей, завантаження, генерацію — проти
  зловживань за відсутності реєстрації (обмеження §6).
- **Валідація файлів** за типом і розміром; антивірус/скан за потреби на етапі пілоту.
- **Модерація (MVP-базова):** ліміти + ручний інструмент адміна для блокування
  галереї за viewToken (беклог — автоскан вмісту).
- **GDPR:** мінімізація даних (немає акаунтів/PII, окрім опційного e-mail для
  відновлення в майбутньому), EU-регіон сховища, політика видалення галереї.
- **Авторське право:** при створенні галереї — чекбокс-підтвердження прав на
  зображення; згенерований опис — похідний контент, відповідальність на власнику
  (обмеження §4) — фіксуємо в UI та логах згоди.

## 9. Доступність (WCAG 2.2 AA) — first-class

Продукт для незрячих → доступність самого застосунку обов'язкова, інакше він
безглуздий.
- Семантичний HTML, коректні ARIA-ролі, керування з клавіатури, логічний порядок фокуса.
- Підтримка скрінрідерів (VoiceOver/TalkBack/NVDA); озвучені статуси (aria-live) для
  завантаження/готовності офлайну.
- Доступний медіаплеєр (клавіатурні контроли, підписи станів).
- Контраст, масштабування тексту, відсутність пасток фокуса.
- **Автоперевірка:** axe-core у CI + ручне тестування зі скрінрідером.

## 10. Структура репозиторію (монорепо)

```
canvascast/
├─ apps/
│  ├─ web/                 # Next.js: PWA (перегляд + редактор) + REST API
│  └─ worker/              # Node + BullMQ: генерація опису та TTS
├─ packages/
│  ├─ db/                  # Prisma schema, міграції, клієнт
│  ├─ core/                # доменна логіка, стиль-промпт, типи, Zod-схеми
│  ├─ providers/           # адаптери LLMProvider / TtsProvider (+ реалізації)
│  ├─ storage/             # S3/R2-клієнт, підписані URL
│  └─ queue/               # налаштування BullMQ, визначення задач
├─ infra/                  # Docker Compose (Postgres, Redis, MinIO), деплой-конфіги
└─ PLAN.md
```

- Менеджер пакетів: **pnpm** (workspaces). Build: **Turborepo** (опційно).
- `web` і `worker` ділять `packages/*` → спільні типи й логіка, без дублювання.

## 11. План імплементації (ітерації)

Пріоритет — **демонстрований повний цикл на хакатоні**, але з кроками, що не
перешкоджають масштабуванню.

### Ітерація 0 — Каркас (день 1)
- Монорепо (pnpm + Turborepo), Next.js, Prisma, Docker Compose (Postgres/Redis/MinIO).
- Схема БД + перша міграція. Базовий layout із a11y-примітивами.
- Заглушки адаптерів `LLMProvider`/`TtsProvider`.

### Ітерація 1 — MVP: повний цикл (хакатон, ядро)
Мета: **власник створив галерею → завантажив фото → згенерував опис+аудіо → отримав
QR → відвідувач слухає**.
1. Створення галереї без реєстрації (view/edit токени + QR).
2. Завантаження зображень (multipart, валідація) → S3/MinIO.
3. Метадані картини (автор/рік/техніка/контекст).
4. Черга + воркер: LLM-опис (Claude vision) → TTS (безкоштовний дефолт) → збереження.
5. Редактор: статуси задач (polling/SSE), ручне редагування тексту, перегенерація.
6. Публічний перегляд за viewToken: список картин, доступний плеєр (play/pause/
   перемотка/швидкість) + текст.
7. QR-код і посилання (перегляд + редагування).

### Ітерація 2 — Офлайн і надійність
- Service Worker + Cache API + IndexedDB; «Завантажити галерею» зі статусом і
  версіонуванням.
- Ретраї/ліміти вартості у черзі; стани `failed` з повтором.
- Мультимовність описів (uk/en) — ФВ 12.

### Ітерація 3 — Безпека, модерація, доступність
- Rate-limiting, валідація файлів, базова модерація/блокування.
- axe-core у CI + ручний a11y-аудит зі скрінрідером.
- Підтвердження прав/згоди, політика видалення галереї (GDPR).

### Ітерація 4 — Масштабування та монетизація (пост-хакатон)
- Апгрейд TTS (ElevenLabs/Azure) через адаптер; A/B якості голосу.
- Відновлення доступу через e-mail (знімає ключове обмеження §2).
- Підписки/цінові рівні, облік вартості на галерею, CDN, автоскейл воркерів.
- Спостережуваність (Sentry, метрики черги), SLA 99%.

## 15. Стан реалізації (2026-11-16)

Реалізовано ітерації 0–2 і основу ітерації 3. Інструкція із запуску — у `README.md`.

**Зроблено**
- Монорепо (npm workspaces), Docker Compose (Postgres, Redis, RustFS як S3-сховище), схема БД і міграція.
- Повний цикл: створення галереї без реєстрації → завантаження фото → відомості про картину →
  генерація опису й аудіо через чергу → ручне редагування з автоматичним переозвученням →
  QR-код і посилання → перегляд відвідувачем.
- Адаптери: LLM — Gemini (free tier) з резервною моделлю на випадок 503/429 і mock; TTS — Edge
  (безкоштовно, без ключа), Gemini, mock. Черга підлаштована під безкоштовні ліміти: до 4 задач
  на хвилину, 5 спроб із паузами 20–160 с.
- Достовірність: назву, автора, рік і техніку диктор оголошує перед описом дослівно з відомостей
  власника (в обхід моделі); роки в тексті, яких власник не давав, позначаються «перевірте».
- Офлайн: service worker, збереження галереї одним натисканням, статус готовності,
  пропозиція оновити застарілу копію, перемотування аудіо з кешу.
- Доступність: семантична розмітка, керування фокусом, озвучення статусів, цілі дотику від 48px,
  контраст 7:1, світла й темна теми, Media Session (керування з екрана блокування).
- Безпека: токени 192 біти, обмеження частоти запитів, перевірка файлів за вмістом, денний
  ліміт генерацій на галерею, підтвердження прав на зображення, видалення галереї.

**Відхилення від плану (свідомі спрощення)**
- npm workspaces замість pnpm + Turborepo (pnpm не встановлено; для цього розміру достатньо).
- Нативні HTML-елементи замість Radix/React Aria; `fetch` з опитуванням замість TanStack Query.
- Service worker написано вручну, без Workbox (логіка невелика, менше залежностей).
- Офлайн-маніфест об'єднано з `GET /api/v/:viewToken/gallery` (версія + адреси медіа).
- Окремого ендпоінта «лише переозвучити» немає: збереження тексту переозвучує автоматично.
- TTS за замовчуванням — Edge замість Piper: якісніший український голос і нуль налаштувань.

**Перевірено вручну через API (2026-11-16, справжні Gemini та Edge TTS)**
створення галереї, завантаження (JPEG/PNG/WebP приймаються, GIF і не-зображення відхиляються),
генерація й озвучення, редагування тексту з переозвученням, зміна порядку, видалення картини й
галереї разом із файлами, QR, Range-запити аудіо, ізоляція галерей, обмеження частоти запитів.
Інтерфейс у браузері та офлайн-режим на телефоні ще не перевірено.

**Ще не зроблено**
- E2E-тести (Playwright) і автоматична a11y-перевірка (axe-core); ручний аудит зі скрінрідером.
- Інструмент адміністратора для блокування галерей (поле `blocked` у БД уже є).
- Відновлення доступу через e-mail, монетизація, хостинг, Sentry (ітерація 4).
